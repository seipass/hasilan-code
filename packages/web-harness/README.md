# Hasilan Code

Pi v1.3.0を基盤にしたローカル単一ユーザー用Web入口。上流CLI/TUIとは独立したworkspaceです。上流コミット: `71023aec1546d6d677a65669c5665c0927ce0dd0`。独自リポジトリは [seipass/hasilan-code](https://github.com/seipass/hasilan-code)、本家の取り込み方は [ルートREADME](../../README.md#本家-pi-との関係) を参照してください。oh-my-piのソース、prompt、fixture、native binaryは使用しません。

## 起動

ビルド済みのnpmパッケージ・GitHub Releasesから導入する場合は、[導入・更新](../../README.md#導入更新)を参照してください。`hasilan-code --version`でアプリと基盤Piのバージョンを確認できます。

### ソースから起動

Node.js 22.19以上が必要です。リポジトリrootで実行します。

```sh
npm install --ignore-scripts
npm rebuild node-pty --ignore-scripts=false --foreground-scripts
npm run build:hasilan
node packages/web-harness/bin/hasilan-code.mjs setup
npm run web
```

引数なしで起動できます。起動ディレクトリを最初のワークスペースとして登録し、入力欄上に作業先のパスを表示します。別のディレクトリで始める場合だけ `--cwd <workspace-directory>` を指定します。サイドバーの「会話」右の「＋」から、ホストOSのネイティブフォルダー選択ダイアログで追加できます。Windowsではエクスプローラー形式のフォルダー選択を開きます。キャンセルではワークスペースも下書きも変更しません。

既定は `127.0.0.1:3080`。`--port 0` はOS割当です。port衝突や明示指定した無効なcwdで終了し、別のport/cwdへ切り替えません。ブラウザーは自動起動しません。表示された認証付き起動URLを手動で開いてください。URLはHttpOnly/SameSite=Strict cookieへ交換され、URLからtokenを除去します。起動URLは秘密として扱ってください。`--no-open`の指定は不要です。

Windowsのnode-pty native installが失敗する場合、Python 3.11/3.12、Visual Studio 2022 C++ Build Tools、Windows SDK、Spectre対応libraryを用意してrebuildします。pipeへのfallbackはありません。Linux向けのプリビルドは同梱していないため、C++コンパイラー・make・Pythonを用意して`hasilan-code setup --build-pty`を実行します。プリビルドまたはビルド済みモジュールが無いまま起動した場合は、ビルド方法を表示して終了し、スタックトレースは表示しません。
ネイティブフォルダー選択はホストのデスクトップ上に表示します。WindowsはPowerShell/WinForms、macOSは標準のフォルダー選択、Linuxはzenityまたはkdialogを使用します。SSHやデスクトップ環境のないホストではダイアログを利用できません。同時に開くダイアログは一つです。

`npm run web` は `dist` の配信用ファイルを使います。Web側のソースを変更した後は `npm run build --workspace=hasilan-code` で更新し、サーバーを再起動してブラウザーを再読み込みしてください。依存するPiのソースも変更した場合は、`npm run build:hasilan`でアプリと依存SDKをまとめてビルドします。配布物の作成・検証・公開方法は[独自CI・リリース](../../README.md#独自ciリリース)を参照してください。

## 会話を始める

- 「新しい会話」で下書きを入力し、送信時に会話を作成します。未送信の入力欄は会話領域の中央に置き、入力欄の上には左にアイコンと Hasilan Code、右に作業先のワークスペースのパスを表示します。送信後の会話では入力欄の上のアイコン・名前・パスは表示しません。モデル未選択なら下書きを保持し、モデル選択または未設定の認証を案内します。通常のEnterは改行、Ctrl/Cmd + Enterは送信です。
- 機能の開始は共通入力欄の `/` コマンドに統一しています。`/hyakki 目的` は百鬼夜行を開始、`/canvas` は設計画面を開き、`/chat` は会話表示へ戻ります。`/goal 目標` はGoalを開始します。`/` の候補は入力ボックスの上に独立したパネルで表示し、入力欄の高さや位置を変えません。機能名・用途・種類を表示し、入力に応じて絞り込みます。↑↓で選び、Enter・Tab・クリックで入力欄へ追加、Escで閉じます。候補を選ぶだけでは実行せず、Ctrl/Cmd + Enterまたは送信ボタンで実行します。不明なコマンドや引数不足はエラーにし、入力を保持します。通常の文章は選択中の会話へ送信します。入力欄の下にコマンド説明を常設しません。
- 入力欄のモデル名・Thinking表示を一つの選択ボタンにまとめています。ダイアログは左がモデル一覧、右がThinking強度の一覧で、両側を独立してスクロールできます。狭い画面でも左右配置です。認証設定のあるプロバイダーのモデルだけを表示し、現在の選択にチェックを付け、モデルが5件以上あるときだけ検索欄を表示します。↑↓で移動、Enterで選択でき、検索中のEscapeは検索語を消去します。モデル選択後は同じダイアログで対応するThinking強度を選べます。新規会話の下書きで未対応のThinking強度を持つモデルへ切り替えた場合はSDKの自動設定へ戻します。モデル未選択なら選択を案内し、選択したプロバイダーの認証が未設定、または全プロバイダーの認証が未設定の場合は設定画面へのボタンを表示します。認証設定のあるプロバイダーに再ログインを求めません。認証とAPIキー入力は設定の「プロバイダー」タブで行います。モデル選択後も下書きは保持します。
- モデル選択パネルは選択ボタンのすぐ上に開き、入力欄の高さ・画面サイズ・サイドバーの幅に追従します。画面内に収まる位置と高さに調整し、開いたときは選択中のモデルをハイライトして一覧内に表示します。検索すると絞り込んだ先頭候補から選べます。
- コンテキスト使用量は送信ボタンのすぐ左に表示します。実行中に停止ボタンへ切り替わっても同じ位置です。使用量はPi SDKによる推定値です。保存済み会話は読み込み時に履歴から復元するため、再起動後もメッセージの送信を待たずに表示します。未実行の会話や実行中の圧縮直後など、まだ計測できない場合は「—」です。
- 会話のモデルは入力欄で選択します。モデル・Thinkingの選択はブラウザーのlocalStorageへ保存し、新規会話・ワークスペース切り替え・再読み込み後も引き継ぎます。既存会話はその会話に保存された設定を優先し、モデル未選択なら送信前に選択が必要です。実行中はモデル・Thinkingとも変更できません。
- 応答の取得に失敗した場合はエラーの詳細を表示します。原因が分からないエラーに接続設定や再認証を案内しません。
- サイドバーの「会話」はワークスペース別のアコーディオンで、その下に各セッションを表示します。ワークスペース名のクリックやEnter/Spaceは開閉だけを切り替え、表示中の会話・作業対象は変更しません。検索中は一致したワークスペースを開いて表示します。配下の会話を選ぶと作業対象をそのワークスペースに切り替え、履歴を開きます。会話タイトルは最初のユーザーメッセージから取り、後続の指示では変更しません。幅を超える名前は「…」で省略し、全体はホバーで確認できます。下書きと表示中の会話・ワークスペースはブラウザーのlocalStorageに保存します。ブラウザーの保存機能が使えない場合も入力・送信は可能ですが、再読み込み後の下書き復元はできません。
- ファイル・チーム・ツール・端末は「詳細」のタブで切り替えます。「詳細」ボタンでパネルを開閉し、左端をドラッグすると幅を調整できます。ファイル画面は左に開いたファイルのタブと読み取り専用プレビュー、右にファイルツリーを表示します。境界をドラッグしてツリー幅を調整でき、各領域は独立して縦スクロールします。長いコード行の横スクロールはビューア内に収め、ツリー・境界・タブ列の位置を保ちます。狭い画面ではプレビューとツリーの最小幅を縮め、パネル幅に収まるよう調整します。長いファイル名は「…」で省略し、全パスはホバーで確認できます。タブは詳細の表示切り替えでも保持し、作業フォルダーの変更でリセットします。タブ選択やパネル再表示で外部変更を取得します。
- スクロール領域には細い、画面の配色に合わせたスクロールバーを使います。操作中は見やすくし、端末の文字表示領域のスクロール幅は変更しません。
- ファイル・端末のタブは中クリックでも閉じられ、ドラッグで順序を変更できます。順序変更で表示中のファイルやPTYは切り替えません。タブ順序はブラウザー内の表示状態です。
- ファイル・端末のタブを表示領域の左・右・上・下の端へドラッグすると分割位置をプレビューし、ドロップするとその側にタブを配置します。タブ列の小さなアイコンからも左右／上下の2ペインにできます。常設の分割選択欄はありません。各ペインでタブを独立して選択し、境界のドラッグまたは矢印キーでサイズを変えられます（Shiftで大きく移動、Home/Endで最小／最大）。タブの「⇄」または別ペインの中央へのドラッグはタブの移動です。最後のタブを移動・閉じて空になったペインは自動で統合します。統合アイコンはすべてのタブをまとめ、ファイルやPTYを閉じません。ドラッグ中のEscapeは分割をキャンセルし、詳細パネルを閉じません。分割状態とタブの所属はブラウザー内の表示状態です。
- ファイルツリーからは最後に操作したペインへファイルを開き、既に開いているファイルや行リンクはそのタブのあるペインを選択します。ページ位置・Markdownの表示方法はタブごとに保持し、他ペインのタブ選択で動画を読み直しません。端末の各ペインにある「＋」はそのペインへ作成し、移動・分割方向の変更・統合で既存の接続や端末エミュレーターを作り直さず、PTYの変数や実行中の処理も保持します。
- コードファイルは拡張子に応じてシンタックスハイライトします。MarkdownはGFM対応のプレビューを既定にし、「ソース」で行番号付き表示へ切り替えます。プレビューは全ページを取得してから描画し、取得途中のファイル変更や省略された長い行では不完全な文書を描画せずエラーにします。行リンクはソース表示で該当行を開きます。raw HTMLは実行しません。
- 動画（MP4/M4V、WebM、MOV、OGV）はファイルビューア内で再生・一時停止・シークできます。再生可能なコーデックはブラウザーに依存します。先頭の形式情報を確認し、動画全体をメモリへ読み込まず、認証付きの部分取得で配信します。動画ファイルが変更された場合はタブを選び直して読み込みます。
- 「端末」タブは会話とは独立したPTYです。「＋」で作成し、端末内のタブで切り替えます。別の詳細タブへの切り替えや詳細パネルの非表示中もPTYは継続し、非表示の端末も出力・終了状態を受け取ります。「×」または中クリックはPTYを終了してタブを閉じます。シェルのキー入力は会話画面のショートカットへ伝播せず、バックグラウンドの出力は入力欄のフォーカスを移しません。
- パネルとファイルツリーのサイズ境界はキーボードでも操作できます。矢印キーで16px、Shift + 矢印キーで48pxずつ調整し、Home/Endで最小・最大にします。ツール呼び出しはカードのアイコンと左側のアクセント帯を使わず、英語ラベルで種類別に折りたたんで表示します。read は行リンクやディレクトリ、write は作成内容と版、edit はパッチ・ファイル別の状態・差分、bash はコマンド・終了コード・出力、browser はタブ・ページ・操作対象・スクリーンショット、web_search は検索条件と出典、team はタスク・依存関係・実行結果を表示します。元の入力と結果の詳細は折りたたんで確認できます。writeの結果に含まれるエージェント向けの編集指示は画面に表示しません。ファイルのパスや行番号を選ぶとファイルを開きます。
- 実行中の追加指示は「完了後に続ける」または「実行中に指示」で送信できます。空の入力欄では送信ボタンが停止ボタンになります。
- サイドバー全体は300msで滑らかに開閉します。広い画面では会話領域と一緒に移動し、狭い画面では左からスライドして背景の暗転と同期します。途中で開閉を反転しても現在位置から続け、閉じた領域はクリック・キーボード操作の対象から外します。ワークスペースのアコーディオンは対応ブラウザーで内容の高さと透明度を連続的に変え、矢印の回転を合わせます。会話の新着、モデル選択、設定、詳細・端末パネルにも短い状態遷移アニメーションがあります。OSの「視覚効果を減らす」設定（`prefers-reduced-motion`）では動きと遅延、スムーズスクロールを無効化します。ストリーミング中の本文やパネルのドラッグ操作には移動アニメーションを適用しません。
- サイドバーの開閉ボタンは開閉状態によらず画面左上の同じ位置に置き、ロゴはサイドバー上部の右側に表示します。ボタンの位置は開閉アニメーション中も変わりません。
- 右の詳細サイドバーも左と同じ300ms・減速カーブで開閉します。広い画面では会話領域と幅調整の境界が連動し、狭い画面では右からスライドします。途中反転と「視覚効果を減らす」に対応し、閉じたパネルはクリック・キーボード操作の対象から外します。幅のドラッグ調整には開閉アニメーションを適用しません。
- 会話・設定・チーム詳細のアコーディオンも対応ブラウザーで滑らかに開閉します。入力欄の自動伸縮は180ms、ファイルツリーの開閉は260msです。設定と右サイドバーのタブ切り替え、チームの担当変更、ファイルタブの並べ替え・削除は対応ブラウザーで内容と位置を短く補間します。設定の表示中は背後の右サイドバーとファイルタブを補間対象から外し、設定の切り替えで背後を明滅させません。入力欄と端末は再作成せず、「視覚効果を減らす」では追加の動きを無効化します。
- ファイルビューアの本文は読み込み後に180msでフェード表示します。ファイル・行ページ・Markdownの表示方法を切り替えた際も適用し、ツリーの矢印とタブ・選択項目の色も180msで変化します。スクロールや幅のドラッグには追加のアニメーションを付けず、「視覚効果を減らす」では無効化します。
- チーム詳細は担当・状態・現在の作業を先に表示し、過去の実行と識別子は必要時だけ開けます。会話内のAI応答には重複する名前ラベルを付けません。
- 閉じた「思考」には推論の先頭を一行で表示し、開くと全文を読めます。通常テキストは [Gen Interface JP](https://gen.typesetting.jp/)（npm版0.8.0）、コード・ファイルソース・端末は [UDEV Gothic](https://github.com/yuru7/udev-gothic)（v2.2.0）を使用します。両書体はホストから配信し、外部CDNは必要ありません。UDEV Gothicのライセンスは `public/fonts/UDEVGothic-LICENSE.txt` です。
- 左サイドバーの表示文字と、閉じたツール呼び出し・思考の見出しは文字選択の対象外です。検索欄と、開いたアコーディオンの本文は引き続き選択できます。

画面・タブ・起動ログの名称は `Hasilan Code`。npmパッケージ名は `hasilan-code`。ロゴとfaviconは `public/icon.svg` を共有し、配色は `src/client/styles.css` の指定パレットを使います。

## 設定と永続化

設定画面は認証・使用量・保存・実行環境の状態と操作を表示します。保存・更新・削除に失敗した場合は、失敗した操作とエラーの詳細を表示します。保存先や権限、内部動作の説明は以下のドキュメントにまとめています。

Piとは設定・認証・会話履歴を分離します。既定の保存先は `~/.hasilan-code/agent`。`HASILAN_CODE_AGENT_DIR` に絶対パス（先頭の `~` も可）を指定すると変更できます。Pi用の `PI_CODING_AGENT_DIR` は参照しません。

| 保存内容 | 専用ディレクトリ内のパス |
|---|---|
| アカウント認証・保存済みLLM認証 | `auth.json` |
| モデル定義・モデルカタログキャッシュ | `models.json` / `models-store.json` |
| SDK設定・OAuth用のインストールID | `settings.json` |
| Webの検索・チーム設定 | `web-harness/settings.json` |
| Brave/Tavily/Exa/Firecrawl の検索キー | `web-harness/credentials.json` |
| ワークスペース・セッション・チーム・実行状態 | `web-harness/state.json` |
| 会話履歴（Pi SDKのJSONL形式） | `web-harness/sessions/` |
| ワークスペースごとのCanvas設計 | `web-harness/canvases/<workspace IDのSHA-256>.json` |

プロジェクト設定は `<workspace>/.hasilan-code/settings.json`。拡張・スキル・プロンプト・テーマ・`SYSTEM.md`・`APPEND_SYSTEM.md` の自動探索も `.hasilan-code` を使います。Piの `~/.pi/agent` やプロジェクトの `.pi` は自動で読み込み・変更しません。以前Pi側に保存した認証・Web設定・履歴は移行せず、そのまま残します。共通の `AGENTS.md` と `.agents` のスキル、およびプロバイダーの環境変数は引き続き利用できます。

Hasilan Codeの標準AIプロンプトは製品名を含めず、Pi本体のドキュメント案内を省きます。ツールの使い方・操作上の制約・プロジェクトの指示は残します。ユーザー指定の `SYSTEM.md` や拡張によるプロンプト置換は変更しません。

モデル・Thinkingの選択はブラウザーごとに保存します。会話ごとの設定は引き続きホストに保存し、ブラウザーの選択で既存会話を上書きしません。Webの検索・チーム設定ファイルとは独立しており、共有SDKのモデル既定値は変更しません。

アカウント認証は独自SDKのプロバイダー認証を使い、専用の `auth.json` に保存します。認証情報の更新もSDKが管理します。ログインは明示クリックで開始し、表示したリンクをユーザーが開きます。デバイスコード、選択肢、コード・コールバックURL入力に対応し、キャンセル・画面を閉じる操作・ホスト終了で待機を中止します。同時ログインは一つです。失敗時は一つのエラー表示に詳細をまとめ、ログインボタンで再試行できます。送信に失敗した入力は入力欄に残します。認証成功後はモデル一覧を更新します。モデル選択パネル・設定画面で入力したLLM APIキーは現在プロセス専用で、再起動すると失われます。キー・トークンの値はGETやWebSocketへ返しません。

Web検索は Brave、Tavily、[Exa](https://exa.ai/docs/reference/search)、[Firecrawl](https://docs.firecrawl.dev/api-reference/endpoint/search) に対応します。「設定 → 検索」で各サービスのAPIキーを保存し、既定のサービスを選びます。`web_search` の `provider` で呼び出しごとに明示選択もできます。期間指定はExaでは公開日による絞り込み、FirecrawlではWeb検索の `tbs` を使用します。キーの有無は表示しますが、検索の成功や残量は接続テストしていません。

会話のauthorityはSDKのJSONLです。再起動時に実行中runは`interrupted`となり、自動再実行しません。未消費入力も自動再送しません。空sessionの未作成JSONLは正常ですが、materialized会話のJSONLが消失した場合はmissingとして扱います。

### アカウントの使用量

「設定 → 使用量」で、接続中の対応プロバイダーからアカウント全体の情報を取得します。既存の認証を使い、推論リクエストは発行しません。会話内のトークン集計やSDKの概算料金から契約の残量を推測する機能ではありません。

| 接続 | 取得する情報 |
| --- | --- |
| CommandCode | 月間・購入分などのクレジット残量、5時間・週次の使用枠、請求期間のリセット日時 |
| Devin | 日次・週次の使用枠、プロンプト・フロー・Flexのクレジット、無制限枠、リセット日時 |
| OpenAI / OpenAI CodexのChatGPT認証 | 短期・長期・コードレビューの使用枠、追加クレジット、リセット日時 |

取得はタブを開いたときと「更新」を押したときだけです。常時ポーリングせず、別タブへの切り替えや設定画面を閉じる操作で取得を中断します。プロバイダーごとに20秒でタイムアウトし、一社の失敗で他社の表示を失いません。取得できなかった値を残量ゼロや無料へ置き換えず、APIが返す項目だけを表示します。OpenAIの通常のAPIキー認証は契約使用量の取得対象外です。

CommandCodeは`api.commandcode.ai`への接続先URLで識別するため、`models.json`で独自名を付けた接続も対象です。クレジットはAPIが返した単位で表示し、プラン名から月間上限を固定値で補完しません。[公式の使用枠の説明](https://commandcode.ai/docs/resources/usage-limits)も参照してください。

取得処理はSDKの`Provider.getAccountUsage`機能として定義します。Web側は認証済みプロバイダーを列挙し、公開してよい結果だけを認証付き`GET /api/account-usage`で返します。生の認証情報や上流のエラーレスポンス本文は返しません。これらの照会APIには非公開のものもあり、提供元の変更や権限・契約によって取得できない場合があります。

### Devinアカウント

「設定 → プロバイダー → Devin → Devinでログイン」から、次の接続方法を選びます。

- **ブラウザーでログイン**: Devinの認証画面を開き、PKCE付きのログインを行います。ブラウザーから戻れない場合は、ログイン後のコールバックURLを貼り付けます。
- **このPCのDevin CLIから読み込む**: CLIの`credentials.toml`を明示操作で読み取ります。元ファイルは書き換えず、起動時の自動読み込みもしません。
- **セッショントークンを入力**: Devinのセッショントークンを直接入力します。

認証情報は専用の`auth.json`へ保存します。ログイン時に利用可能なモデルとThinkingのバリアントを取得し、アカウントに対応するカタログを`models-store.json`へ保存します。再起動時は保存済みカタログを復元します。認証が失効した場合は再ログインしてください。

Devinは独自SDKの標準プロバイダーとして扱い、認証成功後のモデル一覧も`ModelRuntime`が直接更新します。Web側での個別登録や、ログイン処理から一時キャッシュを介してモデル一覧を受け渡す処理はありません。

[dsh-plugin-oauth-subs](https://github.com/xxww0098/dsh-plugin-oauth-subs/tree/main/src/oauth/devin)のMITライセンスの実装を参照した、Connect/protobufによるネイティブ接続です。Devinの外部エージェントやクラウドセッションへ処理を渡すのではなく、Hasilan Code側のエージェントとツールを使います。専用の複数モデル実行が必要なFusionは一覧に表示しません。Devin公式の連携ではなく、非公開プロトコルの変更やアカウントの利用制限で接続できなくなる場合があります。

会話内のDevin使用量は返されたトークン数とキャッシュ読取・書込から集計します。モデル単価を取得していないため、USD料金は`未計測`と表示します。料金不明を無料として扱わず、Devinの契約料金やACU使用量への換算も行いません。

## キャッシュと使用量

会話の入力欄右側にあるコンテキスト使用量をクリックすると、この会話の担当・モデル別の未キャッシュ入力、キャッシュ読取・書込、出力トークン、概算USD料金をポップオーバーで確認できます。チーム図の左上にある「チームの使用量」からは親と全子の保存済み使用量を確認できます。ヒット率は`読取 / (未キャッシュ入力 + 読取 + 書込)`で、率の単純平均ではありません。この入力合計がゼロなら「—」、応答・補助処理の記録がない場合は「未計測」です。

使用量の画面には集計値と操作だけを表示します。算出方法・料金の注意事項は、この節にまとめています。

集計元はSDKの会話JSONLです。ストリーム途中の値を重複加算せず、モデル変更前や圧縮前の履歴、保存された要約・prewarm・ツール内モデル呼び出しの使用量も含めます。モデルが記録されていない補助処理は、直前のモデルへ推測で帰属させず別行に表示します。再起動・再読み込み後も履歴から復元します。料金はSDKのモデルカタログに基づく概算で、契約や実際の請求額とは異なる場合があります。

Goal・百鬼夜行の状態は、意味のある変更時だけ非表示のコンテキストとして会話履歴へ追記します。タイムスタンプだけの更新では追記しません。圧縮で状態が失われた場合は次のリクエストで再投入し、一時停止・完了・解除も最新状態として伝えます。過去の発言やツール結果は書き換えません。

新しく組み立てる標準プロンプトでは、共通のプロジェクト指示・スキル・作業先を担当固有の追加指示より前へ置きます。ツール名の順序とスキーマのオブジェクトキーも安定化します。対応する本家OpenAIのAPIキー経路では、無効化したツールの宣言を残して`allowed_tools`で現在の利用範囲を制限します。同じ定義を再有効化しても重複宣言しません。定義変更、未対応モデル、互換エンドポイント、ChatGPTログインでは従来の送信方式へ戻します。サーバー側の実行権限や子への委譲制限は緩めません。

これらはキャッシュ可能な先頭部分を保つための処理で、ヒット率・費用削減・応答時間を保証しません。実APIでの比較では、同じモデル・同じタスクで入力ヒット率と総料金を確認してください。

## 実行モデル

session選択は表示だけを切り替えます。非選択sessionと子agentの実行は継続します。teamのconcurrencyはrootを含むteamごとのlimitです。`team.wait`中はpermitを返し、結果を返す前に再取得します。子は独立会話ですが同じworkspaceのlive fileを共有します。

### Hyakki-Yako（百鬼夜行）

共通のチャット入力欄で `/hyakki ログイン機能を実装し、独立レビューして結果を統合する` のように送信します。親AIは調整専任で、読み取りによる状況確認・作業分解・子への依頼・結果確認を担当します。実装・編集・コマンド実行は子エージェントへ委譲し、親の実行ツールから書き込み・編集・bashを除外します。子は委譲前のツール権限の範囲で作業できます。独立した作業は同時実行上限の範囲で並列に進め、依存する作業は先行結果を受け取ってから開始します。担当の名前・役割・人数は目的に応じてAIが決め、固定の架空チームは表示しません。

親AIの指示・応答・最終結果は通常チャットに表示し、専用のスウォーム画面には切り替えません。右サイドバーの「チーム」はタブ全体を親子関係の図に使い、進行状況を左上、選択した担当の詳細を右下、拡大縮小の操作を右上に重ねます。詳細は高さを制限して内部でスクロールし、図の表示領域や拡大率を変えません。狭いパネルでは上部の状況と操作を縦に並べ、詳細もパネル内に収めます。作業中・結果待ち・開始待ち・完了・失敗・中止を実際の状態から表示し、結果を待つ相手には破線を使います。ノードは自動配置し、ユーザーによる移動はできません。空白のドラッグで表示を移動し、Canvasと同じくホイールはカーソル位置を中心とした拡大縮小、＋／−は表示中央を中心とした拡大縮小です。全体表示と選択位置への移動もできます。図の見出し・ノード数・操作説明と「ライブ」の表示は置きません。ノードを選ぶと担当内容・結果・履歴を右下に表示し、親AIの会話は切り替えません。「会話を開く」で明示的に移動します。子への補足送信・担当と子孫の停止・親からチーム全体を停止する操作も残しています。進捗率や完了予定時刻は推測しません。広い画面では開始時にチーム図を開き、狭い画面では上部の「百鬼夜行」ボタンから開けます。会話・画面を切り替えても実行は継続します。

開始には待機中のルート会話が必要で、実行中の子がある場合やGoalが有効な場合は開始できません。目的が未達なら、親の応答終了後も自動で調整を続けます。ユーザーの追加指示と子の結果を優先し、子の処理中には無駄な継続呼び出しをしません。達成時は `team` ツールの `{ action: "swarm", op: "complete", reason: "確認結果" }`、入力待ちなら `op: "block"` で理由を報告します。完了には成功した子の作業と全子孫の停止が必要です。本文で「完了」と述べるだけでは終了しません。進展のない継続・同じ操作の反復・失敗・ユーザーの停止では一時停止し、無条件に再試行しません。状態と理由を保存し、ホスト再起動時も一時停止にして自動再実行しません。再開する場合は `/hyakki 目的` で明示的に開始してください。費用上限はないため、必要に応じて停止してください。HTTP APIは `POST /api/sessions/:sessionId/swarm`、本文は `{ "objective": "目的" }` です。

旧形式の百鬼夜行データは、会話履歴・目的・実行記録を保持して一時停止状態へ移行します。起動時に自動実行せず、`/hyakki 目的` で明示的に開始します。不正な保存データは上書きせず起動エラーにします。

### Canvas

共通のチャット入力欄で `/canvas` を送信すると設計画面を開きます。モデルの選択や会話の作成は不要です。空の画面の「ノードを追加」または上部バーの「＋ ノード」で始め、ボード上の「編集」またはダブルクリックで名前と説明を入力します。ノード右の「接続」から接続先のノード・左の「ここへ」を選ぶと線でつながります。接続中の案内と中止操作は上部バーに表示し、Canvasの位置や大きさを変えません。Escでも接続を中止できます。ノードのドラッグ・矢印キーでの移動、ホイールでの拡大縮小・全体表示に対応します。

設計タイトル・概要・保存・ファイル操作は上部の表示操作バーにまとめています。選択したノードの名前・説明・座標・削除、選択した接続のラベル・削除は同じバーの「選択項目」から操作します。ノード削除時はその接続も削除します。説明用サイドバー・ノードや接続の一覧・件数表示は置かず、その領域をCanvasに使います。実行状態を示すチーム図とは別の、ユーザーが編集する設計図です。`/chat` で会話へ戻ります。

「保存」でワークスペースごとにホストへ保存し、「ファイル」の「保存済みを読み込む」で取得します。同じ設計を別の画面が先に更新した場合は上書きせずエラーにします。未保存の内容も「JSON 書き出し」で取り出せます。会話との切り替えでは下書きを保持し、未保存のまま別ワークスペースへ移る場合は確認します。ページを閉じる前に保存してください。ノード・接続の件数上限はありません。保存データの4 MiB上限と文字数・座標・ID・接続先の検証は維持します。

新規ノード・接続のIDは `n1`・`e1` のような短い連番です。新規エージェント・実行・子会話も `a1`・`r1`・`s1` のようなIDを使い、保存済みの最大番号から次を割り当てます。既存のIDや会話履歴は書き換えません。

送信先を「会話」または「Hyakki-Yako」にして「AI に相談する下書きへ」を選ぶと、現在の設計の指示と JSON をワークスペース内の `.hasilan-code/canvas/design-<短いID>.txt` に保存し、共通入力欄にはそのファイルを読む指示と相対パスだけを追加します。JSON本文を入力欄へ展開しません。毎回別ファイルを作るため、以前の下書きが指す設計を上書きしません。Hyakki-Yakoを選んだ場合は `/hyakki` を付け、通常チャットに戻ります。内容を確認・追記してから送信してください。追加操作だけではAIを実行せず、ファイル保存に失敗した場合も下書きを変更しません。設計画面の「保存」とは独立しており、送信後の編集は自動反映されません。ノードや接続自体を実行する機能ではなく、設計内の文字列をシステム指示へ昇格させません。

HTTP APIは `GET /api/workspaces/:workspaceId/canvas` と `PUT /api/workspaces/:workspaceId/canvas`。保存時は取得した `{ revision, design }` を送り、成功するとrevisionが増えます。古いrevisionは409、重複ID・存在しない接続先・上限外の値は400です。`POST /api/workspaces/:workspaceId/canvas/compose` は現在の `{ revision, design }` を受け取り、指示と JSON の txt を新規作成して `{ path }` を201で返します。保存済み設計のrevisionは変更しません。

### Goal モード

共通のチャット入力欄で `/goal 目標` を送信すると開始します。指定するのは目標だけで、Goal専用のトークン予算・使用量表示・予算による停止はありません。ルート会話だけで利用でき、選択したモデルと認証が必要です。実行中の会話では開始できません。通常の会話は自動継続しません。

Goalが実行中なら、応答終了後も同じ会話で目標への作業を続けます。ユーザーの追加指示と子の結果を先に処理し、チームの同時実行上限を守ります。モデルは `goal` ツールの `complete` で達成、`block` で入力待ちを理由付きで報告します。本文で「完了」と述べるだけでは終了しません。自動継続でツールによる進展がない場合や同じ操作・結果を繰り返した場合、モデルの失敗・中断時は一時停止します。

`/goal pause` または会話の停止は、Goalを保存して親と子の実行を中止します。`/goal resume` は同じ目標を再開し、`/goal drop` は終了状態を残します。`/goal` または `/goal status` で状態を表示します。目標が `pause` などの操作名から始まる場合は `/goal create 目標` を使います。達成・終了後は新しいGoalを作成できます。ホスト再起動時は実行中のGoalを一時停止にし、明示的な再開までモデルを呼びません。

モデル呼び出しには選択したプロバイダーの料金・制限が適用されます。Goalに費用上限はないため、必要に応じて一時停止・終了してください。旧保存データの予算・使用量は起動時に除去し、以前の予算到達状態は一時停止として読み込みます。

HTTP APIは `GET /api/sessions/:sessionId/goal` と `POST /api/sessions/:sessionId/goal`。POSTは `op: "create" | "get" | "pause" | "resume" | "drop"` を受け、createには `objective` を指定します。状態は会話のWebSocket更新にも含まれます。

`team` ツールでは独立した作業を `spawn` で同時に依頼できます。`workflow` は最大32件の `tasks` に `name`、`task`、任意の `dependsOn`（先行タスクの名前の配列）を指定します。依存グラフを起動前に検証し、独立した作業は並列実行、成功した作業の結果は依存先の入力に渡します。失敗・中止した作業の依存先は起動せず `skipped` を返します。`wait` の `mode:"any"` は最初の完了・失敗時点、既定の `all` は全対象の終了時点で返ります。子の終了は親の実行中に通知され、親が既に作業を終えていれば続きの実行を開始します。

子の完了・失敗・中止通知は、ユーザー発言ではなく補足コンテキストとして親へ渡します。チャットでは「コンテキスト」と担当名・終了状態を付けて折りたたみ表示し、開くと結果とagent/run/injection IDを確認できます。通知はSDKの`custom_message`に送信元と結果のsnapshotを保存します。モデルへ渡す際は通常のuser-role contextへ変換し、system指示には昇格しません。既存履歴のユーザー発言は書き換えません。

コンテキストの注入と実行要求は別の操作です。注入だけではモデルを呼び出しません。実行中の親にはtool結果の一組が揃った後で取り込み、必要なら同じ実行内で続きを処理します。親がidleならteamのpermitを取得してcontext-only runを開始し、通知をユーザープロンプトとして再送しません。`team.wait`中はpermit再取得後に通知を渡します。停止した親やホスト再起動後には自動再実行しません。

担当の定義は `<workspace>/.hasilan-code/agents/<name>.json` または `~/.hasilan-code/agent/agents/<name>.json` に置きます（保存先を変更した場合は `HASILAN_CODE_AGENT_DIR/agents/`）。例: `{"name":"reviewer","description":"変更点を検証","systemPrompt":"問題と根拠を報告する","tools":["read"]}`。`model` は `{ "provider": "...", "id": "..." }` で任意に指定できます。`team` の `profiles` で一覧を取得し、`spawn` または `workflow` の各タスクの `profile` に名前を指定します。プロジェクト側が同名の共通定義より優先されます。全定義を読み取り・検証し、不正なJSONやシンボリックリンクはエラーにします。`tools` は親の利用可能なツールの部分集合だけ許可します。

ユーザーterminalはworkspace所属の実PTYで、agent bashと別物です。session切替、panel非表示、接続切れ、agent Stopではkillしません。明示Closeとhost終了でkillします。再接続snapshotはheadless xtermの画面（scrollback 2000行）で、全文logではありません。操作権は一接続だけで、引き継ぎは明示操作です。

## ファイルとHashline

viewerはread-onlyで、agentの既読行に影響しません。外部editor/PTYの変更はRefreshで取得します。アプリ内commitはfiles_changed通知で再取得します。

Hashlineは独立実装です。全文由来の`[PATH#TAG]`と`LINE:TEXT`を使い、表示済み行だけを編集できます。編集結果には新しいタグと編集行の番号付きpreviewを返します。位置と内容が変わっていない既読行、および完全に表示されたpreview行は、新しいタグで続けて編集できます。移動した行や省略されたpreview行は再readしてください。

古いsnapshotは1ファイル8版・セッション全体64版・raw bytes合計32MiBを上限として保持します（単一の巨大な最新版は保持できますが、他の履歴は破棄します）。古いタグによる編集は、既読対象と隣接する内容から現在の位置を一意に確認でき、全hunkの位置ずれが一致する場合だけ復旧します。MarkdownとTS/JSでは、囲んでいる構文とその開始行から対象までの内容も照合し、別の関数や節への付け替えを拒否します。構文を証明できない場合も再readが必要です。対象変更・曖昧な位置・未知または衝突するタグ・改行/BOMの変化・古いsnapshotでの`REM`/`MV`は拒否します。同じ16bitタグでもraw bytesが違えば変更なしとは扱いません。復旧後もcommit直前に現在のraw revisionとbytesを検証します。復旧を前提に古い位置を使わず、エラー時は再readしてください。

patchは`*** Begin Patch` / `*** End Patch`の両方を付けるか、両方を省略できます。外側の空行は許可しますが、本文の`+`欠落やunified diffは推測で補正しません。文法エラーはpatchの行番号・対象行・修正方法を返します。`N*`はMarkdown headingとTS/JS構文blockのみで、他言語は明示rangeを使用します。BOM/元の改行形式を維持し、mixed EOLは編集を拒否します。`write`は新規file専用です。

workspace外path、ADS、drive-relative、外部symlink/junctionはファイルサービスで拒否します。ただしこれはsandboxではありません。agent bash、ユーザーPTY、ブラウザーは起動ユーザーの権限で実行されます。multi-file commitも外部editorに対する原子的transactionではなく、I/O失敗時はfile別の適用結果を返します。
