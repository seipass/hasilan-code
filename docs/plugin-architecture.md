# Hasilan Code のプラグイン設計

Pi の実行エンジンを固定し、Hasilan Code の製品機能は同じ拡張 API を使う標準プラグインとして提供する。標準構成は現在の機能とデータを引き継ぐ。完成時には標準プラグインをすべて外してもホストが起動し、自作プラグインだけを読み込める。

## 製品としての完了条件

DeepSeek Harness を参考に、次の項目を満たす。モデルの応答品質や推論性能の改善は、この再設計の評価対象から外す。

| 項目 | 確認方法 |
| --- | --- |
| フル機能 | 標準構成を起動し、既存の主要機能と保存データを利用できる。 |
| 操作体験 | 初回起動、ワークスペースを開く、会話を再開する、プラグインやテーマを切り替える、という操作を Web とデスクトップで確認する。依存不足や起動失敗が起きたときも、画面から原因を確認して復旧できる。 |
| ミニマルな構成と画面 | 標準プラグインをすべて外してホストを起動できる。標準画面は日常操作をすぐ使える位置に置き、追加機能は必要に応じて開ける。 |
| 軽量・高速 | 無効な実装は評価せず、任意の機能は初回利用まで起動を遅らせる。移行前と同じ環境で、起動時間、初回操作の待ち時間、メモリを測る。 |
| 豊富なプラグイン | 標準機能をプラグインとして配布し、追加、無効化、交換を管理画面から行える。ツールの追加、画面全体の交換、テーマの切り替えを実際の配布物で検証する。 |
| 自作プラグイン・自作テーマ | 公開 API とサンプルを使い、本体の変更なしに作成・読み込み・配布できる。自作の画面とツールだけで Pi の応答を取得できる。 |

## ホストとプラグインの境界

現在は Web と Electron が同じ `startHarness` を使い、そこで Canvas やチーム管理、HTTP ルート、終了処理を組み立てている。例えば Canvas の差し替えには、保存処理に加えて、サーバーのルートと画面側の入口も差し替える必要がある。プラグインの有効化単位は、これらをまとめて登録・解除できる機能単位とする。

ホストは Pi への接続、起動と終了、プラグインの選択と状態管理、認証済みの通信経路を提供する。ツール、モデル接続、会話の保存・検索、文脈の加工、Goal、百鬼夜行、Canvas、画面、テーマ、外部連携は順次プラグインへ移す。Pi の実行時セッションと、ユーザーが交換できる会話の保存・表示は別の責務として扱う。

## 第1段階の提案

リポジトリ内の Chord を候補とする。Chord にはプラグインの検出と読み込み、およびサーバーとブラウザー向けのビルドがある。まず既存のパッケージ構成で配布できるかを小さな試作で確認する。

- マニフェストに一意の ID、対応するホスト API のバージョン、必要な機能と対象環境を記載する。設定で有効になったプラグインだけを評価する。単一の実装を選ぶ機能では、どの実装を使うか設定で指定する。
- プラグイン間の呼び出しは、ホストが解決する型付きのサービス契約を使う。例えば百鬼夜行は会話プラグインの内部クラスを読む代わりに、会話を作成・取得する契約を要求する。変更通知にはイベントを使い、操作の成功・失敗を呼び出し元に返す処理にはサービス呼び出しを使う。
- 必須依存の不足や循環は起動前に検出する。開始に失敗したプラグインは途中の登録を解除し、依存する機能だけを停止する。停止時は依存順の逆に、新規リクエストの受付、実行中の処理、登録済みのルートや購読を片付ける。無効化やアンインストールでユーザーデータは削除しない。
- 初期のサーバープラグインは信頼済みコードとして扱う。API の利用範囲を宣言しても、同じ Node プロセスで動くコードの OS アクセスは制限できない。未信頼のコードを扱う段階では、隔離された実行環境と、ホストが認可するファイル・ネットワーク操作が必要になる。

最初の試作は、状態を保存しない標準ツールを一つ選び、Pi のツール登録に接続する。同じ契約で自作ツールに置き換えられること、有効化していない実装が評価されないこと、読み込みに失敗してもコアが起動することを確かめる。ここで必要になった API を初版とし、画面や保存用の契約は移行時に定義する。

## 移行と完了条件

### サーバー用プロファイル

Web とデスクトップの共通ホストは、起動時にエージェントディレクトリの `plugins.json` を読み込む。未設定ならすべての組み込みプラグインを有効にする。ID の値を `false` にすると無効になり、モジュールへのパスを指定すると置き換わる。相対パスは `plugins.json` のディレクトリを基準に解決する。新しい ID で追加もできる。変更はホストを再起動すると反映される。

```json
{
  "web-search": false,
  "local-tools": "./plugins/local-tools.cjs"
}
```

モジュールは `apiVersion = 1` と、`tools(session)`、`handleApi(request, response, url, parts)`、`panel`、`theme` のうち少なくとも一つを名前付きでエクスポートする。`tools` は Pi のツール定義の配列を返し、セッション ID、ワークスペース ID、作業ディレクトリを参照できる。API ハンドラーはホストが認証したリクエストを受け取り、応答を書いた場合は `true`、担当外の場合は `false` を返す。読み込むモジュールはホストと同じ権限で実行される。読み込みに失敗した ID は起動ログに出る。

ブラウザーは認証済みの `GET /api/plugin-profile` から、有効なプラグインと外部画面の一覧を取得する。画面の名前とアイコンを、サイドバーの「新しい会話」の直下に表示する。ボタンを押すとセッションを保ったまま、登録した画面がメイン領域に表示される。Canvas は従来どおり `/canvas` でも開ける。無効化するとサイドバーのボタン、コマンド候補、画面が消え、保存データは残る。

外部画面を配布するには、プラグインのモジュールと、同じディレクトリ内のブラウザー用 JavaScript を用意する。たとえば `plugins.json` で `"notes": "./plugins/notes/plugin.cjs"` を指定し、次の内容を置く。

```js
// plugins/notes/plugin.cjs
exports.apiVersion = 1;
exports.panel = { title: "Notes", script: "panel.js" };
```

```js
// plugins/notes/panel.js
document.currentScript.dispatchEvent(new CustomEvent("hasilan:panel", {
  detail(root, { insertDraft, signal }) {
    const button = document.createElement("button");
    button.textContent = "下書きに追加";
    button.addEventListener("click", () => insertDraft("メモ"), { signal });
    root.append(button);
  },
}));
```

画面コードは最初に開いたときに読み込まれる。登録関数には `workspaceId`、`signal`、`insertDraft(text)`、`setDirty(boolean)` が渡る。画面は同じワークスペース内の移動で保持される。ワークスペースを離れると `signal` が中断され、登録関数が返した後片付け関数が呼ばれる。画面コードはアプリと同じオリジンで実行するため、信頼できるプラグインを使う。

Chord のローダーは試用時点のパッケージから公開されていない。最初のツール移行は Node のモジュール読み込みで構成し、画面やサービスを移すときにローダー選定を再検討する。

組み込みの配色は `theme-default` として同梱する。独自の配色を配布する場合は、プラグインの `theme` に `title`、`dark`、`light` を指定する。それぞれの配色は `background`、`foreground`、`accent` に6桁の16進色を、`contrast` に0〜100の整数を指定する。

```js
exports.apiVersion = 1;
exports.theme = {
  title: "Dusk",
  dark: { background: "#102030", foreground: "#e9eef4", accent: "#aecaff", contrast: 55 },
  light: { background: "#faf0e6", foreground: "#252945", accent: "#3a5199", contrast: 50 },
};
```

たとえば `"dusk": "./plugins/dusk.cjs"` をプロファイルに追加して再起動すると、「設定 → 外観 → 配色」で選択できる。選択は設定に保存され、配色プラグインを外すと標準配色に戻る。標準のカスタム色は保存済みの設定から引き続き使える。

`"goal": false` にすると、Goal のコマンド、入力欄の操作、API、ツール、自動継続を無効にする。会話に保存済みの目標は保持される。

`"hyakki": false` にすると、百鬼夜行の開始・再開、Canvas からの送信先、モデルのスウォーム操作、自動継続を無効にする。既存の目標、チーム、担当エージェント、会話は保持される。通常のチーム操作には `team-tools` を使う。

既存のセッション用ツールは `hashline`、`shell-process`、`browser-tools`、`computer-tools`、`jev-computer`、`web-search`、`team-tools`、`goal` として同梱し、標準で有効にする。`hashline` を無効化したとき、別のプラグインが提供しない `read`、`edit`、`write` は Pi の既定ツールにも戻さない。`shell-process` は長時間実行用の `shell_process` を担当する。

セッションに紐づくリソースを持つプラグインは、停止・削除時の `closeSession(sessionId)` とホスト終了時の `close()` をエクスポートできる。ホストは登録の逆順で呼び出し、各呼び出しの失敗を記録して残りの後片付けを続ける。

### 段階

1. プラグインの選択・起動・停止と Pi のツール登録をつなぐ。標準と自作を同じ経路で読み込む。
2. 画面全体の提供元、画面内の追加領域、テーマを登録できるようにする。現行の画面を標準プラグインとして提供し、別の画面で起動できることを Web とデスクトップで確認する。
3. Goal・百鬼夜行・Canvas を各機能単位で移し、モデル・会話・文脈管理などにも順次適用する。移行前に作成したデータを標準構成で開き、更新し、再起動後に読み直せることを確認する。保存形式を変更する場合は、旧データからの移行と失敗時の復旧を検証する。
4. 管理画面と自作プラグイン・テーマのサンプルを用意する。依存不足や起動失敗は原因と対象を表示する。
5. 標準構成と最小構成で、起動時間・初回操作の待ち時間・メモリを同条件で測る。標準プラグインなしでホストを起動し、自作の画面とツールだけで Pi の応答を取得できることを確認する。
