# アニメーションの不連続と修正

調査・修正日: 2026-10-25

対象は `packages/web-harness/src/client`。前回の「未適用箇所」の一覧とは別に、アニメーションの中断、重複、読込後のレイアウト変化を調べた。機能の追加ではなく、既存の動きの連続性を修正した。

## 修正済み

| 場面 | 原因と具体例 | 修正 |
| --- | --- | --- |
| 会話一覧、モデル候補、作業タブなどの並べ替え | 移動中に次の更新が来ると、前回の終点から再開する。0→100の途中50で次の終点が200になると、100へ飛んでから動く。 | キャンセル前の進捗から表示位置を保存し、50から200へつなぐ。移動先が変わらない更新でも残りの移動を継続する。 |
| 予約中の追加指示などの高さ変更 | 中断時に表示中の高さを捨て、前回の目標の高さへ飛ぶ。 | 現在の高さから次の高さへ補間する。 |
| 分割表示、ファイルツリー、引き継ぎ候補のレイアウト変更 | 移動・拡縮の途中で更新すると、以前の目標位置・サイズから再開する。 | 途中の位置とサイズを保存する。 |
| 通知、候補一覧などの素早い開閉 | 表示途中に閉じると透明度1、閉じる途中に開くと透明度0へ戻る。 | キャンセル前の透明度から逆方向へ動かす。 |
| 高さを縮めて閉じる通知などの再表示 | 閉じる途中で開くと高さ・余白が即座に全量へ戻る。 | 高さ、上下の余白、パディングも途中の値から復帰する。 |
| Computer useの連続スクリーンショット、画像の連続読込 | 読込イベントごとに透明度0.25からのフェードを積み重ね、明滅する。 | 同じ要素のフェードを置き換え、現在の透明度を引き継ぐ。 |
| ファイル読込完了 | 消えかけの読込表示の下へ本文を置き、140ms後に読込表示が消えるため本文が上へずれる。 | 読込表示と本文を同じグリッド領域へ重ねる。音楽ビューは領域全体の高さを維持する。 |
| 分割境界をドラッグする操作 | レイアウト切り替えの補間が残っていると、直接のリサイズ操作と競合する。 | 境界をつかんでいる間はレイアウト補間を止める。 |
| チーム内の担当選択 | 詳細カードだけの更新で右パネル全体を画像化してフェードする。関係図・操作ボタンまで巻き込む。 | View Transitionの対象を担当詳細だけにする。 |
| 設定タブ、チーム画面への切り替え | 親の画面切り替えと子の登場アニメーションが重なり、透明度が二重に変わる。 | 設定本文の重複フェードと、詳細ビュー内のチーム本文の重複フェードを除く。 |

共通処理: `Motion.tsx`。個別の調整: `SplitLayout.tsx`、`files/FilePane.css`、`GlassSurfaces.css`。

## 検証と限界

- 実際の共通フックを呼ぶ回帰テストで、修正前の位置・高さの飛び、フェードの重複、開閉反転の不連続を再現した。修正後は7ケースが成功。
- クライアントとパッケージの型検査を実施。全体テストやPC・スマホの網羅確認は実施していない。
- これはフレームレートの計測結果ではない。多数のソース行の個別ぼかし、背景画像と複数パネルのぼかし、大規模な関係図の描画負荷は端末依存の候補であり、今回確認した不具合と区別する。表示効果や機能は計測なしに削除していない。
