## 条件と測定方法

- 実際の Electron メインプロセス、プリロード、Web UI、バックエンドを隔離先に生成して起動。両者とも同じ現行依存関係を使用し、対象3コミットの変更ファイルだけを差し替えた。通常の配布ビルド出力や作業ツリーは書き換えていない。
- アプリごとに独立したデータディレクトリとワークスペースを作成。ユーザーの会話・認証・設定は使用していない。
- 合成会話48件、各128メッセージ、履歴ファイル合計 49.9 MiB。48件すべての使用量集計完了を確認してから測定した。
- TypeScript ファイル12枚、各6,000行。すべてを順に開いてから測定。生成されているエディタ本体は修正前12個、修正後1個。
- スクリーンショットと同じ ArtifactStore に、1 MiB の合成画像バッファを36件投入。実際のデスクトップ画面の取得やLLMの呼び出しは行っていない。
- 外部ウィジェットへのネットワーク要求は両者とも固定応答にした。背景画像・端末・内蔵ブラウザの追加タブは使用していない。
- 実行順は before → after → after → before → before → after。各試行は新規プロセス・新規プロファイル。画面サイズは通常の既定値 1360×900。
- OS が報告する PrivateMemorySize64 をメインプロセスと全子プロセスについて合算した。これは専有コミットメモリであり、物理RAMの占有量そのものではない。Working Set の合計は共有ページを重複計上するため比較の主指標にしていない。
- 通常の待機値に加え、バックエンドとレンダラーのガベージコレクションを明示実行した値も記録した。強制回収は計測時だけの操作で、製品には追加していない。

## 解釈

この負荷では、会話全文の常駐抑制、非表示エディタの停止、画像バッファのディスク退避により専有メモリが減った。実データでの削減量は会話の大きさ、タブ数、画像数、AI実行状態で変わる。空のホーム、実行中のAI、数GBの実履歴、長時間使用時のピークをこの数値で保証するものではない。
